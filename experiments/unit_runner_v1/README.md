# 整单元起草实验

此目录保存可重复使用的输入准备、审稿回放和用量汇总脚本。真实响应保存在被 Git 忽略的 `.local_projects/` 中；不会把测试草稿写入正式小说。

## 本轮样本

- 图书馆现实短篇：`examples/unit_brief.json`，正文上限 4500，偏好 3200。用于检查小单元是否能自然收束、物件和人物行动是否连续。
- 历史 U002 校园修仙单元：从旧 Harness 的明确作者合同和共同前两章准备输入，正文上限 14999，偏好 10000。只作为历史样本，不代表作者当前采用的方案。

`prepare_u002.py --source-project <旧实验项目> --out-dir <新目录>` 提取作者输入及共同前情，并记录来源哈希。它不会读取旧机器续写作为新写作前情。

`prepare_kimi_pilot.py` 准备本地 K3 迁移样本：沿用作者输入与正式前情，把作者已认可的局部编辑示范单独标为风格参考，偏好 6000、上限 7999 非空白字符。该样本同时更换模型与提示，不能用于控制变量比较。研究及实测限制见[剧情与情感研究](../../docs/research/KIMI_K3_STORY_AND_EMOTION_2026-09-05.md)。

`audit_archived_unit.py --help` 查看整稿审稿回放参数。该回放知道要审查历史稿件，不能伪称盲测。

`summarize_runs.py --run-dir <运行目录> --run-dir <另一个目录> --out <汇总.json>` 读取各运行的 manifest 和 usage。失败运行也应列出，不能只保留好看的成稿。供应商没有返回的用量无法计入。

## 如何解释结果

检查分成三层：

1. 工程：完整稿是否保存、字数是否小于上限、能否恢复、原文和状态是否受到保护。
2. 叙事事实：找书是否重复、消耗是否凭空恢复、人物知识是否越界、失败后的成功是否有新条件。
3. 阅读体验：动机可信度、行动张力、重复说明、人物声音、余韵。这部分需要通读和作者意见。

单元测试验证第一层及部分证据绑定机制，不验证小说好不好。结构合法的引用不等于证据支持结论；机器未报问题不等于无错。

本轮是开发中的诊断实验，提示词、分段和思考配置均有变化，不是单变量对照。不能从某次更好的稿件推断某种架构或模型全面优胜。应先确定作者认可的参考稿，再固定输入和配置，对比修改负担与作者盲选结果。
