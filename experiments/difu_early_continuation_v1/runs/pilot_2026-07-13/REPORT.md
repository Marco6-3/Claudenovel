# 《地府微信群》早期续写盲测报告（两断点试运行）

## 结论

当前架构已经值得进入小规模真实使用，不建议继续先堆新 Agent。三路差异化 Writer 能稳定产出完整候选，双顺序 Judge 能识别一处稳定胜者，也能在差距过小时返回 `judge_uncertain`，没有强行制造确定答案。

这轮是真实 Codex 模型推理，不是 Mock：3 个相互隔离的 Writer 分别按“事件因果”“人物选择与代价”“读者牵引”策略，在两个断点各写一章；另有 2 个隔离 Judge 以正序和反序评审。它没有调用仓库配置的外部 LLM API，因此不消耗项目中的供应商 API key/额度，但会使用当前 Codex 任务的模型推理资源。

## 方法

- 断点：第 11 章后续写第 12 章位置；第 16 章后续写第 17 章位置。
- Writer 只看到切点之前的两章、公开状态和以人类外部创意为最高优先级的合同。
- 每个断点生成 3 篇候选；目标原章作为第 4 篇匿名混入。
- 独立质量与作者路线贴合度分开评，不合并成单一总分。
- 两个 Judge 分别看相反候选顺序；只有映射回来源后胜者一致，才正式选中。
- 泄漏检查没有发现隐藏专名；候选与目标原章最长连续相同片段仅 6–8 个字符。

## 结果

### 第 11 章后

| 文本 | 独立质量 | 作者路线贴合度 | 说明 |
|---|---:|---:|---|
| candidate_01 | 9.062 | 6.180 | 事件因果策略 |
| candidate_02 | **9.190** | 6.160 | 人物选择与代价策略；正反序一致胜出 |
| candidate_03 | 8.580 | 5.995 | 读者牵引策略 |
| 匿名原章 | 6.045 | **9.950** | 不满足同一公开单元范围，仅作诊断 |

这里不能用 9.190 对 6.045 宣称模型超过原作。公开创意要求在本章解决林萧拦截，而原章有意停在鬼王与保镖即将交手的尾钩；原章因此被两个 Judge 判定未完成同一单元。聚合器已支持把这种原章标记为 `ineligible-source`：保留分数，但排除正式质量胜负。

### 第 16 章后

| 文本 | 独立质量 | 作者路线贴合度 | 说明 |
|---|---:|---:|---|
| candidate_01 | 9.248 | 8.075 | 正序 Judge 胜者 |
| candidate_02 | **9.332（诊断均值）** | **8.090** | 反序 Judge 胜者 |
| candidate_03 | 9.013 | 8.075 | 路线功能同样接近原章 |
| 匿名原章 | 7.135 | **10.000** | 满足同一公开合同 |

这一断点的三篇生成稿在独立质量上都高于匿名原章，但正序选 candidate_01、反序选 candidate_02，所以正式结果是 `judge_uncertain`，不能把均值最高的 candidate_02 当作自动胜者。更稳妥的表述是：并行生成已产出至少两篇很强的可用稿；最后选择需要人类 A/B 或第三个 Judge。

三篇生成稿的作者路线贴合度约 8.08/10，说明即使没有看到隐藏目标章，也能较准确地猜中“能力兑现—发现身边鬼物—建立交涉接口—留下校园灵异钩子”的叙事功能；具体鬼物身份与事件细节则保持了差异。

## 下一步优先级

1. 先投入封闭使用：每章默认 3 个差异化 Writer，并行后盲评；不要继续增加 Agent 角色。
2. 加一层人工二选一：只展示原章/候选或前两名候选，不显示来源，允许“平局/都退回”。模型 Judge 的 9 分段明显偏拥挤，人类偏好是最后证据。
3. 全六断点前先做“原章可比性”检查：原章若不满足同一外部创意合同，只测路线贴合，不进入质量胜负。
4. 记录成本与时延：并行 Writer 缩短墙钟时间，但会增加总 token；只有成稿采用率提升才能证明值得。
5. 扩展到六个断点后再决定是否需要架构创新。优先观察重复率、Judge 顺序不一致率、人工改稿量和每篇采用成本，而不是继续堆复杂度。

## 文件

- 每个 case 的 `quality_result.json`：独立质量聚合结果。
- 每个 case 的 `route_result.json`：作者路线贴合度聚合结果。
- 每个 case 的 `candidates/`：三篇真实模型续写。
- `public/writer_prompt.md`：Writer 实际看到的无泄漏提示词。
