# Unit Branch-first 真实 API 结果

日期：2026-08-02
模型：三个 Planner 与双顺序语义审计均使用 `deepseek-v4-flash`。
结论：两轮候选均未通过差异门，没有选择分支，没有激活 ArcContract，也没有生成正文。

## 实验意图

在不超过 1.2 万字的单元内，让凌默建立身体异常监测方法，并用可回看证据确认高三频繁去图书馆与传承集中显现有关。作者锁同时要求：

- 校园现实问题是主体；
- 图书馆关联由记录建立；
- 凌默通过谨慎观察和控制变量推进；
- 不写鬼怪追逐或图书馆恐怖副本。

完整输入位于 `unit_branch_demo_intent.json`。

## 第一轮：角色提示但没有语义门

目录：`unit_branch_demo_project/unit_branches/unit_branches_0001_277eefe4aacc/`

三个隔离 Planner 分别使用规则机制、人物选择、线索重构角色。结构字段的逐字比较显示每对六轴都不同，但人工检查发现三条路线均为：

```text
异常日志 -> 控制变量 -> 学业/人际代价 -> 确认图书馆关联 -> 异常数据尾钩
```

随后增加双顺序语义审计。审计认为三条路线高度同构，而且正序、逆序的逐轴判断不完全一致，因此：

- `diversity_order_consistent=false`
- 三对 `semantic_passes=false`
- `blocking=true`

这验证了旧 Branch-first 研究的结论：字段和措辞不同不代表事件机制不同。

## 第二轮：正交机制提示 v2

目录：`unit_branch_demo_project/unit_branches/unit_branches_0001_bbe4b07019c8/`

改动：

- 规则路线允许日志与控制变量作为核心；
- 人物路线明确禁止把日志相关性或控制变量作为高潮；
- 线索路线明确禁止前瞻实验，要求使用既有借阅、考勤、伤势或同学记忆反推。

实际结果：人物 Planner 仍回到控制变量；线索路线虽然增加历史材料，最终仍以日志、对照和相关性确认作为核心。双顺序审计本轮结论一致，但三对均被判为 0 个实质差异轴：

- `diversity_order_consistent=true`
- 三对 `semantic_difference_count=0`
- `blocking=true`

## 架构结论

Branch-first 不能成为每个单元的强制步骤。本例中作者已经锁定“控制变量确认图书馆关联”这一方法；若系统为了凑出三种核心机制而改变它，反而违反作者意图。

后续规划路由应是：

```text
作者已经锁定核心机制或可变轴不足三个
-> Direct Unit Plan

作者只锁目标与边界，仍开放冲突空间、触发、机制、高潮、代价、尾钩中的至少三个轴
-> Unit Branch-first
-> 双顺序语义差异门
-> 作者选择一个分支
```

Branch-first 只负责探索作者留下的自由预算，不能拿“多样性”覆盖作者锁。当前系统在两轮真实实验中均正确停止，没有自动选择一个看似不同但实际同构的方案。
