# 完整单元草稿运行器

作者提供单元简报和明确选择的前情，系统在隔离草稿中写完整个单元、通读审阅，并对事实、因果、作者约束、结局问题及重大文字问题最多修订两轮。结果始终待作者审核，不会调用 commit，不会更新 accepted 或 NovelState。

## 使用

```powershell
python -X utf8 agent_writer_cli.py --project-root .local_projects/unit-demo unit-run --run-id library-v1 --brief examples/unit_brief.json
```

已有小说用 `--context-file` 传入明确选定的前情、人物设定、作者风格样例，可重复传入。程序不搜索或自动读取其他小说。配置使用现有 Writer、PLANNER、UNIT_SCORER 的环境变量；没有角色配置时使用默认模型。

本地写作配置已迁移到 Kimi K3。新环境可设置 `LLM_MODEL=kimi-k3`、`LLM_BASE_URL=https://api.moonshot.cn/v1`、`LLM_API_KEY`、`LLM_REASONING_EFFORT=low`、`LLM_TIMEOUT=180` 和 `LLM_CONTEXT_WINDOW_TOKENS=1048576`；密钥只放在忽略的本地环境文件。K3 始终思考，客户端发送 `max_completion_tokens`，不发送温度或 DeepSeek thinking 开关。角色专用配置优先于通用配置；请求失败不会自动更换提供商。当前 low 完成过整单元流程，high 在规划请求超时；这不是两种配置的文学质量比较。

启用上述上下文窗口配置后，新客户端在生成前调用 Kimi token 估算接口，检查输入加预留输出；超限明确停止，不暗中删掉前情。`--max-prompt-chars` 默认仍是 90000 字符保护，可根据输入提高；它和 token 窗口是两种不同限制。`usage/` 同时保存上下文预检查和实际返回的用量，估算不冒充账单用量。当前没有自动笔记压缩。

简报可增加 `reader_experience`（希望读者关心什么）与 `relationship_focus`（希望关系如何通过互动发展）。计划增加选择压力、关系变化和单元关系发展，写作同时考虑行动后果与人物回应。审稿增加引用实际段落的阅读效果观察；这些观察不作为自动重写门槛，也不是读者实测。机制与限制见[剧情和情感研究](research/KIMI_K3_STORY_AND_EMOTION_2026-09-05.md)。

也可以把作者方案直接写成 Markdown 或文本，用 `--brief 单元方案.md --max-chars 29999`，不需要 JSON。系统将方案全文作为作者输入；`--preferred-chars` 可指定软偏好。对于 JSON，命令行长度参数覆盖同名字段；不合法的明确篇幅组合会报错。

`--critic-thinking auto` 默认对名称以 DeepSeek 开头且已配置 thinking 协议的审稿模型启用推理，其余保持原配置。此选择来自实际回归：关闭推理时漏掉重复找书的主因果错误，启用后找出了对应前后章证据。可以显式指定 enabled、disabled 或 omit；模型/代理须支持对应协议，auto 不代表对所有模型都做过兼容性验证。Writer 和 Planner 保持各自配置。

结构化简报为 UTF-8 JSON，可从示例改写。必需字段为 title、premise、ending；其他字段见示例。`max_chars` 最大 29999，`preferred_chars` 是软偏好，必须不大于上限。正文按非空白字符计数，含标点、数字、字母，不含程序添加的章节标题。不保证凑满偏好长度。

运行结果位于项目的 `drafts/units/<run-id>/`：

- `完整单元稿.md`：选定版本的整稿。
- `交稿说明.md`：机器发现的问题、补全设想、需要作者决定的方向。
- `manifest.json`：输入指纹、状态、模型配置指纹、逻辑调用次数和输出指纹。
- `versions/`、`chapters/`、`reviews/`：初稿及修订历史。
- `requests/`、`responses/`、`usage/`：提示词、原始响应和供应商返回的 token 使用量。没有返回的计量不补造。

只读查看状态：

```powershell
python -X utf8 agent_writer_cli.py --project-root .local_projects/unit-demo unit-run-status --run-id library-v1
```

原有 `unit-status` 仍指向旧 Arc 状态，新入口使用 `unit-run-status`，避免破坏原有命令。

## 中断恢复与修改

输入、代码、模型配置不变时，重新运行完全相同的命令即可恢复。完成的有效响应会复用，不重新生成。锁随进程退出释放，不需要删除陈旧锁文件。已经完成或需要作者决策的运行只返回状态。

修改简报、前情、代码、运行参数，或者手动编辑已记录输出后，应使用新 run-id。程序不会覆盖用户改过的候选。作者可以另存并编辑整稿；当前入口不负责把它合入正式小说。

升级审稿代码后，不必重新生成已有整稿。保持简报和前情不变，使用新 run-id，并加 `--from-run 旧运行目录`，即可核验旧稿哈希后复制到新运行，只重新审阅与修订。支持初稿已齐、审稿中断的旧运行。原目录保持不变，模型用量重新记在新运行中。

作者读稿后可将反馈写入 UTF-8 文件，追加 `--revision-note 作者反馈.md`。必须同时指定 `--from-run`；系统先按反馈逐章修订整稿，再执行整稿检查和有限修复。旧稿副本保存在 `versions/seed.md`，反馈写入 `input/revision_note.md`，后续只重新审稿时也会继承。该作者定向修订额外花费每章一次调用，不占机器缺陷修复的轮数，但计入 `--max-calls`；它是作者明确要求的改稿，不以旧稿机器分数是否下降来决定要不要执行。机器随后仍可能误判，因此请比较 seed 与新稿。

`awaiting_author` 表示机器终评未留下待修问题，仍须作者看稿；`needs_author_review` 表示完整候选仍有事实、因果、作者约束、结局或重大文字问题，或未闭合；`needs_author_direction` 表示模型提出作者约束/结局上的方向冲突；`interrupted` 表示网络、校验或资源限制中断，可在条件不变时恢复。模型提出的方向冲突也可能判断错误，不等同于作者输入真的有错。

## 成本与能力边界

默认一个规划调用、每章一个写作调用、一个整稿审阅；事实、因果、作者约束、结局问题即使被模型标为 minor，也进入修订。只有 minor 文字意见保持为建议。每轮重新审整稿，最多两轮。跨章问题可指定联动修订前后章。修订版只有在机器待修问题计数（含未闭合惩罚）下降且没有新方向问题时被选中；这是保守停止启发式，不是文学质量保证。误报也可能引发不必要的修订，因此旧稿始终保留。

规划器不能因为作者没有写明动机、误会细节或见面方式就停止。普通创作留白由系统补全并列入 assumptions。规划阶段的作者问题必须逐项附两条不同、确实存在于输入的冲突原话；缺证据先要求重新规划。程序只能验证引文存在，不能证明两条约束真的矛盾，作者方向问题仍可能误报。审稿阶段的问题暂未使用这项双引文验证。

计划只保留每章的主要发展与前后状态。篇幅偏好不超过 4500 时，整个单元合为一次正文生成；较长单元的过度碎分章节会被合并为较长的连续写作段。事件不删除，原计划保存为 `plan_original.json`。合并数基于篇幅偏好估算，不是文学质量判定。运行器给最后的收束预留篇幅；这是防止写到末尾无空间的资源约束，不要求每章凑到指定字数。

审稿先从原文重建开头、转折和结尾的目标状态，再核对因果；不读取 Planner 对自身设计的解释。模型选择当前版本的段落编号，程序从对应段落取出原文，避免抄写时把人名换成代词、破坏引文校验。编号必须属于对应章；跨章问题保留双方证据。模型照样可能引用了不支持结论的段落、漏检或误判，不能以编号合法代替人工阅读。

正文若仅多出一行开头 Markdown 标题及空行，会去掉这行元数据，保留原始响应；不会因此重写整章，也不会截断正文。开启思考的 Writer 使用 16000 初始输出 token 额度，普通模式使用 8000，以减少推理先耗尽额度造成的整次重试；这不是目标正文字数，也不保证响应时长。

`--max-calls` 默认 40，计的是完整模型调用而非 HTTP 次数；每次最多两次传输尝试，截断最多增大预算重试一次。结构/正文校验失败最多再生成一次。失败请求也消耗逻辑额度。`usage/` 仅记录已返回响应的 token，供应商未返回用量或超时请求可能存在未计入的消耗。

初稿生成保留此前已写的单元正文；改章时保留此前工作稿和目标原章，不给 Writer 后章全文，防止把未来经历写成回忆。作者方案仍含未来目标，因此不能宣称彻底防止泄漏。Critic 始终通读完整单元，跨章修复意见可带必要的关联证据。目标原章和修改要求放在提示词末尾，减少改错章或只复印原文的问题。

前情不自动压缩。`--max-prompt-chars` 默认 90000，是字符长度保护，不是供应商 tokenizer 或模型上下文上限。实际需要选择能容纳输入和输出的模型；超限会明确停止，不会静默丢掉作者锁。全书前情很长时，请先选择必要材料或准备可靠摘要。

此版本不包含额外候选采样、自动训练、图检索、逐章正式状态同步。临时连续性以工作稿全文为准，后续是否需要结构化账本应由真实漏项决定。
