# Claudenovel Agent 写作架构：下一步论文调研与实验收敛

日期：2026-07-13  
状态：研究结论；本轮未修改生产架构

## 一句话结论

下一步最值得验证的不是增加 Agent、增加讨论轮次或把三篇正文融合，而是把当前的“3 个完整 Writer 并行”改造成一个实验性假设：

```mermaid
flowchart LR
    A["人类 IdeaContract"] --> B["作者选择的上下文证据包"]
    B --> C["3 张相互独立的剧情 Branch Card"]
    C --> D["合同闸门 + 宏观多样性闸门"]
    D --> E["只扩写最佳 1–2 条分支"]
    E --> F["成对盲评 + 调序复评 + 可弃权"]
    F --> G["只对明确缺陷做一次定向返修"]
    G --> H["人类接受 / 退回"]
```

核心变化是“先低成本探索剧情空间，再把计算投入少数完整正文”，并按任务不确定性决定是否继续生成。外部创意仍是最高优先级；上下文只能提供事实和声音证据，不能自动改写人的创意。

## 当前架构已经做对的部分

- `IdeaContract` 把人类想法、创意锁、禁改项和自由预算设为最高真源。
- Writer 在生成前相互隔离，避免互相锚定。
- 本地硬闸先于语义 Judge，减少明显失败稿的评审成本。
- Judge 使用正反候选顺序，胜者变化时主动返回不确定。
- 最终提交需要人类确认。

这些边界应保留。下一步解决的是搜索效率、多样性质量和评审可信度，而不是扩大 Agent 自主权。

## 论文给出的主要启发

### 1. 测试时计算应该按难度分配，而不是固定 best-of-N

[DSpark](https://arxiv.org/abs/2607.05147) 在 token 推理层根据置信度和负载动态决定验证长度；它不是多 Agent 写作方案，但“只验证可能被接受的草案”这一调度原则可以迁移到应用层。[Scaling LLM Test-Time Compute Optimally](https://arxiv.org/abs/2408.03314) 也显示，不同难度任务适合不同的测试时计算策略，自适应分配比固定 best-of-N 更有效。

对本项目的推断：简单章节可能 1–2 稿就够；只有合同难、候选接近或 Judge 不一致时，才值得生成第三条分支或追加评审。

### 2. 有效多样性比 Agent 数量重要

[Understanding Agent Scaling via Diversity](https://arxiv.org/abs/2602.03794) 指出，同质 Agent 很快饱和，异质信息通道才带来增益；其实验中 2 个异质 Agent 可匹配或超过 16 个同质 Agent。[Diversity Collapse in Multi-Agent LLM Systems](https://aclanthology.org/2026.findings-acl.13/) 进一步发现，密集通信、权威主导和扩大群体都会让开放式创意过早收敛。

对本项目的推断：当前 Writer 应继续保持隔离，但“事件优先、人物优先、读者优先”主要改变写法，没有充分改变核心剧情机制。需要在扩写前明确分配互斥的剧情分支，而不是让 Agent 写完后再期待自然多样化。

### 3. 成对比较通常比绝对打分可靠，但必须处理位置偏差

[LLM Comparative Assessment](https://aclanthology.org/2024.eacl-long.8/) 报告成对比较优于直接打分，同时确认明显的位置偏差。[Replacing Judges with Juries](https://arxiv.org/abs/2404.18796) 表明异质模型组成的评审团可以减少单一模型偏差，但这要求不同模型家族；同一模型重复两次不等于真正的 jury。

[LitBench](https://aclanthology.org/2026.eacl-long.362/) 对创意写作尤其重要：其最强现成零样本 Judge 与人类偏好的一致率也只有 73%，专门训练的奖励模型约 78%。因此 Judge 只能筛选，不能成为“作品好坏”的最终真值。

一篇很新的 [More Convincing, Not More Correct](https://arxiv.org/abs/2607.05904) 在代码和数学任务中发现，reference-free Judge 配合 best-of-N 会偏向“更会说服 Judge”而非真正正确的答案。这不是创意写作的直接证据，但可以推断出同源 Writer/Judge 可能共同放大流畅、完整、像评分模板的稿件；因此本项目需要隐藏原章功能、合同硬闸和人类偏好作为 Judge 看不到的锚点。

### 4. 融合与多轮批评有效，但不是无条件有效

[LLM-Blender](https://aclanthology.org/2023.acl-long.792/) 使用 PairRanker 排序后再用 GenFuser 融合候选；[Collective Critics for Creative Story Generation](https://aclanthology.org/2024.emnlp-main.1046/) 在计划和正文阶段引入多批评者与 leader，并通过人评获得创造力和吸引力提升。

但 [ART: Ask, Refine, and Trust](https://aclanthology.org/2024.naacl-long.327/) 提醒，自我返修并不稳定，应先判断是否需要修，再比较初稿和修订稿。结合本项目实验，直接增加一个“融合全文 Agent”目前缺乏收益空间；一次有明确问题定位、可回退的定向返修更值得测试。

### 5. 长篇连续性需要状态证据，但不能取代人类创意

[Re3](https://aclanthology.org/2022.emnlp-main.296/) 通过总体计划、当前故事状态、续写重排与事实修订提升长故事连贯性；[DOME](https://aclanthology.org/2025.naacl-long.63/) 采用动态层级大纲与记忆增强；[Multi-Agent Character Simulation](https://aclanthology.org/2025.in2writing-1.9/) 则把角色扮演与最终改写分开。

对本项目的推断：如果进入连续网文生产，需要一个由作者确认的 `EvidencePack`，包含最近事件、不可变事实、人物当前目标和少量原文声音样本。它必须低于 IdeaContract，不能自动规划未来剧情。角色模拟仅应在多人物选择冲突明显的章节按需启用，不应成为默认流水线。

## 基于现有六篇续写的离线实验

实验只复用两个无泄漏断点、6 篇真实候选、两次调序 Judge 和已有路线评分，没有重新调用外部 LLM。

### 实验 1：表面多样性与剧情多样性

| 断点 | 平均字符 4-gram cosine | 人工宏观事件 Jaccard | 启发式有效剧情通道 |
|---|---:|---:|---:|
| 第 11 章后 | 0.034 | 0.727 | 1.223 / 3 |
| 第 16 章后 | 0.024 | 0.833 | 1.125 / 3 |

候选在措辞层面非常不同，但宏观事件高度相似：

- 第 11 章后三篇都是“两个保镖施压 → 陈默挨打 → 临时获得地府消耗品 → 借环境逃脱 → 录音和围观者反制 → 林萧留下报复钩子”。
- 第 16 章后三篇都是“珠子激活 → 看见已故男宿舍成员 → 发现长期查寝/点名鬼 → 王冬受威胁 → 利用点名规则拖延 → 危机延后”。

“有效剧情通道”使用 `N / (1 + (N-1) × 平均宏观重合度)` 作探索性折算，不是论文中的正式 `K*`。人工事件标签也不是盲标，因此只能用于发现问题，不能作为正式质量结论。

结论：当前 persona 能制造语言和局部手段差异，却没有打开足够多的剧情空间。这是最需要改进的地方。

### 实验 2：自适应候选数

模拟策略：先只生成事件型 candidate_01 与人物型 candidate_02；如果正反序 Judge 选出同一来源则停止，否则再生成第三稿。

| 断点 | 前两稿结果 | 第三稿作用 | 自适应所需完整稿 |
|---|---|---|---:|
| 第 11 章后 | 两次均选 candidate_02 | 没有改变最佳稿 | 2 |
| 第 16 章后 | 一次选 01、一次选 02 | 03 仍未解决分歧 | 3 |

在这两个样本中，自适应策略从 6 篇降为 5 篇，完整候选数减少 16.7%，没有丢失诊断均值最高稿。按实际字符数估算，可少生成约 3,169 字，即约 15.4%。

限制：只有两个断点，不能据此把默认候选数立即改成 2；它只证明自适应停止值得进入正式对照实验。

### 实验 3：全文融合的理论收益上限

用每个评分维度中三篇候选的最高分拼出一个不可能实现的“oracle 融合稿”，再与最佳单稿比较：

| 断点 | 最佳单稿 | Oracle 维度拼接 | 最大理论增益 |
|---|---:|---:|---:|
| 第 11 章后 | 9.190 | 9.218 | +0.028 |
| 第 16 章后 | 9.332 | 9.340 | +0.008 |

平均理论上限只有 +0.018，而且真实融合还可能破坏声音统一、因果链和创意所有权。

结论：现在不应增加 GenFuser 式全文融合。若要利用其他候选，只提取一条可定位的改进建议，并让原稿与修订稿重新盲比。

### 实验 4：Judge 不确定性来自哪里

- 同一来源在正反顺序中的加权分平均绝对变化约 0.12。
- 第 11 章后的两次候选排序相关性为 0.993；第 16 章后仅为 0.684，并发生胜者变化。
- 将 rubric 改成等权，或逐一移除七个维度，两个断点的诊断均值胜者始终都是 candidate_02。
- 两个断点的第一、二名均值差只有 0.128 与 0.084，且生成稿普遍挤在 9 分附近。

结论：主要问题不是当前权重，而是 Judge 的分数压缩、细微差异辨别和顺序敏感。继续微调 0.15/0.20 之类的权重不会解决核心问题。

### 实验 5：现有 Writer persona 的真实作用

- 人物选择与代价策略 candidate_02 在两处断点都取得最高诊断均值，并领先人物一致性、因果推进、单元弧等多数维度。
- 读者牵引策略 candidate_03 在两处断点都取得最高原创性分，但从未成为整体最佳稿。
- 事件策略 candidate_01 在世界规则或连续性上提供少量补充优势。

结论：persona 不是无效；它制造了维度专长。但它更像“同一剧情的不同写法”，下一轮应保留人物型强基线，同时把其余计算预算用于真正互斥的剧情机制。

## 候选方向的收敛判断

| 方向 | 当前判断 | 原因 |
|---|---|---|
| 增加到 5–8 个完整 Writer | 淘汰 | 同质扩展边际收益低，当前 3 稿已只有约 1.1–1.2 个有效宏观通道 |
| Writer 先互相讨论/辩论 | 淘汰 | 创意任务容易因结构耦合和权威锚定而收敛，且可能削弱人的 IdeaContract |
| 全文 GenFuser | 暂缓 | 本轮 oracle 融合上限平均仅 +0.018 |
| 3 个独立 Branch Card，再扩写 1–2 个 | **首选实验** | 直接针对宏观剧情塌缩，且大纲比完整正文便宜 |
| 两稿起步、按不确定性追加计算 | **首选实验** | 有论文依据；本轮回放节省 16.7% 完整稿且未丢失最佳稿 |
| 成对 Judge + 调序 + 平局/弃权 | **首选实验** | 创意写作零样本 Judge 可靠性有限，当前已出现一次顺序不一致 |
| 定向批评后只修一次 | 第二阶段 | 比全文融合风险低，但必须让初稿与修订稿重新盲比并允许回退 |
| 作者确认的 EvidencePack | 连续写作阶段 | 对跨章一致性必要，但应与单章搜索实验分开验证 |
| 默认角色模拟 | 暂缓 | 只对多人物冲突章节可能划算，不适合每章固定支付成本 |
| 训练专用 Reward Model | 暂缓 | 先积累足够的人类成对偏好；当前两例远不足以训练或校准 |

## 收敛后的下一轮最小实验

### 假设

“独立剧情分支搜索 + 自适应扩写”能在不降低人类创意忠实度的前提下，提高宏观多样性，并减少无效完整正文的 token。

### A/B 条件

- A：当前基线，3 个差异化 persona 直接生成完整正文。
- B：先生成 3 张 250–400 字 Branch Card。每张必须声明核心机制、人物关键选择、代价、高潮兑现和尾钩，并在自由预算维度上与其他分支互斥；通过合同与多样性检查后，只扩写 2 张。
- C：先扩写人物型强基线和一条最远分支；正反序成对 Judge 一致且无 blocking 时停止，否则才扩写第三条。

### 两阶段样本量

1. 可行性阶段：使用《地府微信群》剩余 4 个早期断点，各运行一次 A/B/C。目的是发现明显失败，不作统计结论。
2. 决策阶段：若 B 或 C 没有明显退化，再用全部 6 个断点、至少 3 个随机种子做配对实验，并收集人类盲选。

### 必须记录的指标

- 人类 IdeaContract blocking 率。
- Branch Card 和正文的宏观事件重合度。
- 人类盲选的胜 / 平 / 负，且允许“都退回”。
- Judge 与人类的一致率、调序一致率和弃权率。
- 完整正文数量、输出 token、墙钟时间、最终采用率。
- 最终稿所需人工改动字数或编辑时间。

### 暂定通过门槛

这些门槛仅用于决定是否继续研究，不是产品承诺：

- 相比 A，宏观事件平均重合度至少下降 0.15。
- 人类创意忠实度 blocking 率不得上升。
- B 或 C 至少减少 20% 的完整正文输出 token，且人类盲选胜率没有明显下降。
- Judge 若无法与至少 50 个人类标注对达到可接受一致率，继续只作为过滤器，不获得自动提交权。

## 最终建议

现在先不改主架构，也不要继续广泛探索十几个方向。下一轮只验证两个相互配套的改进：

1. **Branch-first**：在完整写作前制造真正互斥的剧情机制。
2. **Adaptive expand + pairwise abstention**：只在不确定时增加计算，并允许 Judge 承认无法区分。

若这两个方向在全部六个断点和人类盲评中成立，再考虑加入一次定向返修和作者确认的跨章 EvidencePack。全文融合、密集辩论、更多 Writer、角色模拟与奖励模型训练目前都不应进入主线。

## 实验限制

- 只有两个断点、一个 Writer 模型家族和两次 Judge pass。
- 宏观事件标签由研究者事后人工标注，未做独立双人一致性检查。
- “有效剧情通道”和 oracle 融合是诊断指标，不是论文原指标或真实质量上限。
- 没有供应商 token 计费日志，只能用完整稿数与字符数估算成本。
- 所有自动分数最终都需要人类盲评校准。
