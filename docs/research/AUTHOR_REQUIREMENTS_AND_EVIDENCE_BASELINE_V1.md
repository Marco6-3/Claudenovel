# Claudenovel 作者需求与历史证据基线 v1

日期：2026-08-02
状态：当前 API-first 单元剧系统的产品真源；后续架构变更不得与本文件相反。

## 一、最终要做成什么

系统不是无人值守连续写几十章，也不是训练本地模型代替 LLM 写正文。最终产品是：

1. 作者给出“下一个单元剧”的意图、入口状态、目标结束状态、必须兑现和禁改项。
2. 系统完整读取截至切点可见的正文、作者大纲、人物资料、NovelState 和作者反馈策略。
3. LLM API 规划并写完一个正文总量不超过 2 万字的单元；章数由事件自然决定，不设八章或其他硬上限。
4. 每次只激活一章。每章经过合同检查、前文状态评分、作者审核和 StateDelta 更新后，才推进下一章。
5. 单元达到目标结束状态后强制停止，等待作者给出下一个单元意图，不自动延伸更远主线。

## 二、作者权限与修改纪律

优先级固定为：

```text
作者本轮明确意图和禁改项
> 作者确认的设定、正文终稿与反馈策略
> 已接收正文的逐字证据
> 模型证据化推断
> 模型建议和商业小说一般规律
```

- 正文由 LLM API 生成；本地模型训练退出主线。
- 作者人工修改后的章节是新的最高文本真源，系统必须重新计算哈希、评分和 StateDelta。
- 修订任务一次只解决一个问题，采用能解决问题的最小改动。
- 只有确实必须牵动其他情节时才征求作者同意；未获同意不得扩大修改范围。
- 修订章节必须单独保存，供重新发布；不得擅自把全部章节合并覆盖。
- 人工审核包应同时展示前一章、修订章和后一章，但不得把后文信息泄漏给实时续写模型。
- 每次评分、作者接受、人工修改和退回都保留结构化记录，供后续改进提示词、规则和架构。

## 三、《练气仙诀》当前方向锁

- 开篇重点是高三学生面对身体变化、伤势、睡眠、学习、同学和老师询问等现实问题。
- 超自然传承是身体变化的原因和压力来源，不应把前半部写成以恐怖感官刺激为主的悬疑小说。
- 凌默在高三才频繁接触传承，需要由“高三阶段持续去图书馆看书”及传承后果建立因果，而不是偶然撞鬼式触发。
- 空走廊、声控灯、拉长影子等恐怖符号不能替代身体变化、人物选择和现实代价；除非本轮作者合同明确需要。
- 严肃危险场景避免“像散发香味的红烧肉”一类破坏语域的喜剧食物比喻。
- 秦思妍专项、赵灵瑶华山缺席、凌默战斗智取退化等问题必须分开处理；本轮未授权的问题不得顺手修改。

## 四、评分器必须怎样工作

- 评分基于章节合同、作者反馈策略、最近完整章节、NovelState 和可核验证据，不做脱离前文的文学印象分。
- 合同、连续性、人物知识、时间因果、伤势资源、关系线、文风语域和 payoff 分开评分。
- 风格旁注不得混入连续性标签；“红烧肉”案例属于 `style_and_tone`，不是 continuity。
- 总分不能覆盖 blocking；逐字引用不存在、state ID/evidence ID 不存在时整张评分卡拒收。
- API 分数属于 teacher/Silver 信号，不是作者 Gold。作者可接受、修改或退回。
- 绝对总分只作诊断；多个合格方案的选择优先使用匿名 A/B、交换顺序复评，并允许弃权。

## 五、历史数据和训练结果应怎样复用

### 保留并接入

- 三本授权商业小说：作为自然大多 clean 的原文事实基线、切分与检索回归素材；不能冒充作者个人偏好数据。
- 作者真实反馈：作为 `author_locked` 策略、永久回归案例和修改纪律来源。
- DeepSeek Flash 原子事实核验：给定正确证据时可作为低成本建议型核验器。
- NovelState、实体别名、开放线索、最近完整章节：作为事实相关上下文的主入口。
- Branch-first 两切点实验：先比较结构化剧情机制再写正文；分支必须有实质事件差异，Judge 交换顺序后不一致则弃权。
- 旧 Synthetic/模型错例：保留为回归和失败案例，不作为已验证作者偏好。

### 明确停止或降级

- 本地连续性 NLI 模型：三种子 test F1 为 `0.549 ± 0.068`，pair 双条正确率 `0.159 ± 0.153`，不得进入写作链。
- Silver 微调检索器：跨书测试没有稳定超过未微调 BGE；不晋级。
- 普通相似度 RAG：只能召回候选，不能把 Top-K 当事实证明；miss 只能得到 `insufficient_evidence`。
- 让作者判断原始相邻商业章节是否连续：标签几乎全 clean，停止这种标注任务。
- 用已出版小说伪造 A/B 作者偏好：禁止。只有作者真实接受、修改、退回才是偏好 Gold。
- 继续制作 120 张本地模型训练标注：停止。新作者反馈直接服务提示词、回归和 API 评估。

## 六、历史数字的正确解释

- 本地 Silver 连续性模型：full-data 三种子 test F1 `0.549 ± 0.068`；不能接入。
- 同一模型的 pair 排序率三次均为 `0.810`：说明相对比较值得保留，但不能据此宣称绝对分类可用。
- DeepSeek Flash 作者 12 条原子核验：11/12；只是小规模作者校准。
- 三本小说 450 条受控数据：443/450 与旧标签一致；多处分歧可能是旧 Synthetic 标签错误，因此不是 98.4% 真实准确率。
- 隐藏锚点检索 R@10 `0.974`：只证明受控改述下召回较好，且单一 anchor 也可能漏标其他等价证据。
- Branch-first：两个切点中一个明确提升、一个不确定、零个明确退步；支持继续实验，不足以宣称全面优于 direct。

## 七、当前实现顺序

1. 把作者反馈固化为独立 `AuthorPolicy` 数据层，并注入 Planner、Writer、Scorer、Rewriter。
2. AuthorPolicy 变化后，旧评分卡自动失效，必须重评，防止沿用过期偏好。
3. 用第 2 章现有恐怖回摆案例验证评分器能否识别作者方向冲突。
4. Unit Branch-first 只在作者留下至少三个实质自由轴时使用；若核心机制已被作者锁定，则直接生成一个高质量 Unit Plan，不为多样性改写作者意图。
5. 分支方案先过六轴字段门，再过双顺序语义差异门；任一门失败或换序不一致都不允许选择。
6. 选定方案才进入不超过 2 万字的滚动章节写作。
